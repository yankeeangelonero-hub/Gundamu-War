# Wishlist — Mech Bags

Features and ideas the owner or team has expressed interest in, but which are NOT in scope for the current version. Review this list when planning future versions.

Do not implement wishlist items without explicit version scope agreement with Xuanyue.

---

## Deferred from Version 0.1

| Item | Rationale for deferral |
|---|---|
| Cross-bag adjacency bonuses | ARC-003 explicitly excludes this; adds significant design complexity |
| Custom run length / difficulty settings | Premature before the base loop is proven |
| Speed / skip controls in battle viewer | Scoped as optional in Slice 06; defer if it risks the slice |
| `localStorage` run persistence | Deferred — page-reload reset is acceptable for prototype |
| Reroll lock mechanic in shop | Not confirmed as needed; basic reroll sufficient for prototype |
| Item sell mechanic in shop | Adds complexity; not required for V0.1 demoability |
| Mobile-optimised layout | Low priority for prototype; basic responsive is sufficient |

---

## Post-prototype ideas (no version assigned)

| Idea | Notes |
|---|---|
| Limb-themed item set expansion | More items tuned for specific bag identities (e.g. Head = sensor/ranged, Back = heavy support) |
| Cross-bag combos | Synergies that fire when the same trigger item exists in two specific bags |
| Heat / resource system | Adds tactical resource management; not a priority for the fun core loop |
| Persistent ladder / async matchmaking | Requires backend; out of scope until prototype proves concept |
| Custom build sharing (URL or code) | Nice for social play; requires some serialisation work |
| Sound design pass | Placeholder or silent prototype is fine; sound adds polish later |
| Animated mech silhouette frame | Build board could show a stylised mech outline with bag regions highlighted |
| Campaign / story mode | Very speculative; prototype should prove core loop first |

---

## Owner notes (verbatim intent)

> "Shamelessly faithful to Backpack Battles, but with five separate bags."
> "Do not restrict items by body part."
> "Version 0.1 should be simple — explicitly not a complex mech simulator."

Keep these on record. Any proposal to add anatomical restrictions, complex sim mechanics, or lore must be checked against these before scoping.
